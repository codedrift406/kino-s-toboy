# Уведомление о согласии в Telegram

Отдельный Cloudflare Worker принимает `POST /api/reply` от открытки на `https://codedrift406.github.io`. Допустимое тело JSON: `{"answer":"yes","requestId":"UUID"}`. Текст сообщения и получатель задаются на сервере.

## Настройка и публикация

В размещённом обработчике нужны привязка D1 `DB` и два серверных секрета: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. `.openai/hosting.json` объявляет `d1: "DB"` и `r2: null`. Значения секретов вводятся через настройки размещения и остаются вне публичного репозитория.

В этой папке установите зависимости и подготовьте сборку:

```sh
npm ci
npm run build
```

Сборка создаёт Worker в `dist/server/index.js`. При публикации через Sites упаковщик включает миграции из `drizzle/`, а размещение применяет их перед загрузкой Worker. Обработчик должен иметь публичный доступ: открытка отправляет запрос без учётных данных.

После публикации укажите полный HTTPS-адрес с путём `/api/reply` в `window.CINEMA_NOTIFICATION_ENDPOINT` файла `../notification-config.js`. В этом файле хранится только публичный адрес. `GET /health` возвращает `{"status":"ok"}`.

## Проверка

Для тестов нужен Node.js 24 или новее со встроенным `node:sqlite` (проверено на 24.12.0). Из этой папки запустите:

```sh
npm test
```

Тесты используют настоящую SQLite в памяти и SQL миграции проекта, а запросы Telegram заменяют имитацией. Они проверяют доставку, повторные попытки, блокировки, тайм-аут, валидацию и отклонение перенаправлений без отправки сообщений.

## Схема D1

Миграция `drizzle/0000_yielding_the_order.sql` создаёт таблицу `cinema_replies`:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `request_id` | TEXT PRIMARY KEY | UUID ответа |
| `status` | TEXT NOT NULL | `pending`, `failed` или `delivered` |
| `created_at` | INTEGER NOT NULL | Время первого запроса, миллисекунды Unix |
| `updated_at` | INTEGER NOT NULL | Время изменения и метка попытки |
| `telegram_message_id` | INTEGER, допускает NULL | ID отправленного сообщения |

Схема описана в `db/schema.ts`. Для её изменения создайте новую миграцию командой `npm run db:generate` и проверьте SQL. Уже применённые миграции и их метаданные сохраняйте без изменений.

## Сообщение и повторные попытки

Обработчик отправляет фиксированный текст:

```text
💗 На приглашении для Ақерке нажали «Да».
🎬 Можно договариваться о свидании!
```

К нему добавляются время первого запроса в UTC и ссылка `https://codedrift406.github.io/kino-s-toboy/`.

`delivered: true` возвращается после подтверждения Telegram и записи результата в D1. Повторный запрос с уже доставленным UUID возвращает успех без новой отправки. Атомарная блокировка попытки на 60 секунд предотвращает одновременные отправки; активная попытка возвращает HTTP 409. На ответ Telegram отводится 8 секунд.

После явного отказа Telegram возможна повторная попытка. При неопределённом сетевом результате запрос остаётся `pending` до истечения блокировки. Telegram не поддерживает ключ идемпотентности для `sendMessage`: после неопределённого тайм-аута или сбоя между отправкой и записью результата поздний повтор может создать второе сообщение.
